## 1. 문서 개요

### 1.1 목적

본 문서는 "취향 번역기(Taste Translator)" 서비스의 와이어프레임 및 팀 내에서 합의된 정책 결정사항을 기준으로, 화면별 기능·데이터·비즈니스 로직을 정의한 기능명세서이다. 개발팀은 본 문서를 기준으로 구현을 진행하며, 명세 변경이 필요한 경우 팀 합의 후 문서를 갱신한다.

> **표기 규칙**: `{중괄호}`는 사용자의 음악·분석 결과에 따라 바뀌는 값이다. 와이어프레임에 그려진 곡명, 취향 이름, 추천 작품, 사진, 점수 등은 모두 화면 설명을 위한 예시이며 고정 값이 아니다.

### 1.2 용어 정의

| 용어 | 정의 |
|---|---|
| 번역 | 사용자가 고른 음악의 취향을 분석하여 다른 분야(영화·책·여행지·향수)의 추천으로 옮기는 행위 |
| 이슈(Issue) | 분석 1회의 결과 묶음. 취향 프로필과 분야별 추천을 포함하며, 잡지의 "한 호"에 해당한다. `ISSUE 01`, `ISSUE 02` 순으로 번호를 붙인다 |
| 취향 프로필 | 이슈에 담긴 취향 이름, 해설, 태그, 8개 감각 축 점수 |
| 감각 축 | 모든 분야에 공통으로 적용하는 8개의 취향 속성 축. 각 0~100점 (3.4절) |
| 취향 연결(%) | 사용자 취향과 추천 대상이 얼마나 가까운지를 나타내는 점수 |
| 스탬프 | 추천에 대한 사용자의 반응. 4종 중 하나를 선택한다 |
| 취향 카드 | 이슈를 한 장으로 요약한 공유·저장용 이미지 |
| 궁합 | 두 사용자의 감각 축을 비교한 결과(일치율, 겹치는·다른 키워드, 함께 볼 추천) |
| 익명 기기 ID | 로그인 없이 사용자를 구분하기 위해 기기마다 생성하는 고유 번호 |
| 허브 | 하단 탭 바 없이 모든 기능으로 이동할 수 있는 재방문 홈 화면 |

### 1.3 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | 취향 번역기 (Taste Translator) |
| 핵심 가치 | 좋아하는 음악 3~5곡으로 취향을 분석하고, 영화·책·여행지·향수 등 다른 분야의 추천과 "왜 나와 맞는지"에 대한 설명을 제공하는 개인 취향 잡지형 서비스 |
| 핵심 기능 | 음악 검색·선택, 취향 분석(8개 감각 축), 취향 프로필, 분야별 추천 및 연결 근거, 피드백 스탬프, 취향 카드 저장·공유, 아카이브, 친구 궁합 |
| 타깃 사용자 | 취향은 뚜렷하지만 새로운 분야에서 무엇을 고를지 모르는 20~30대 토스 사용자 |
| 플랫폼 | 앱인토스(토스 미니앱), WebView 기반. 와이어프레임은 모바일 390×844 기준 |

### 1.4 전체 기능 구조 (Feature Tree)

전체 기능 흐름도(`취향번역기_플로우차트_v4.png`)를 기준으로 정리한 대분류 구조이다. 세부 항목은 2장 화면별 명세에서 다룬다.

| 대분류 | 주요 하위 구성 |
|---|---|
| 시작 | 진입(토스 앱 실행/공유 링크), 익명 ID 확인·생성, 홈 분기(기록 유무), 공통 레이아웃 |
| 홈 | 첫 방문 홈(서비스 소개, 번역 시작), 재방문 홈·허브(최근 이슈, 지난 이슈 전체 보기, 궁합 안내, 새 번역), 하단 정보 링크 |
| 음악 입력 | 검색(곡·아티스트, 자동완성), 선택 목록(3~5곡, 해제), 입력 검증(최소 3곡/중복/최대 5곡), 제출 |
| 분석 | 분석 연출, 진행 4단계, 완료 시 자동 이동, 예외 처리(시간 초과·재시도·음악 다시 고르기) |
| 취향 프로필 | 취향 이름·해설·무드 이미지·태그, 8개 감각 축, 버튼 액션(카드 공유/궁합/번역) |
| 분야별 번역 | 분야 탭(영화/책/여행/향수), 대표 추천 카드(이미지·취향 연결 %·제목·이유·태그), 다음 추천 |
| 추천 상세 | 기본 정보, 연결 근거(내 음악 → 작품 3줄, 근거 문장), 반응으로 이동 |
| 반응 · 저장 | 피드백 스탬프 4종, 취향 카드(이미지 저장/토스 공유), 흐름 종료(아카이브/처음 화면) |
| 친구 궁합 | 초대 보내기(카드 미리보기/링크 복사/토스 초대), 초대 받기(친구), 궁합 결과 |
| 아카이브 | 이슈 목록, 취향 변화 비교, 기록 관리(전체 삭제 + 확인 팝업) |
| 서비스 정보 | 서비스 소개(AI 문장 안내 포함), 이용 약관, 개인정보 처리방침 |
| 추천 엔진(서버) | iTunes 음악 검색, OpenAI 분석·추천 선정, 분야별 정보 조회(TMDB·카카오 책·OpenTripMap·향수 DB), 검증, 캐싱 |
| 사용자 식별 | 로그인 없음, 익명 기기 ID, 결과 고유 ID, 개인정보 최소 수집 |
| 공통 UI | 토스 내비게이션 바, 뒤로가기·닫기, ⋯ 메뉴(고객센터·신고·공유), 팝업·토스트, 토스 공유 링크 |

> 흐름도의 "관리자(선택)" 영역은 후순위 기능으로 분류되어 본 명세서 범위에서 제외한다(5장 참조).

**MVP 범위**

| 구분 | 포함 기능 |
|---|---|
| MVP 핵심 기능 | 음악 검색·선택 / 분석 진행·재시도 / 취향 프로필(8개 축) / 분야별 번역·추천 상세 / 연결 근거 설명 / 피드백 스탬프 / 취향 카드 저장·공유 / 아카이브·기록 삭제 / 서비스 정보·개인정보 처리방침 |
| 후순위 기능(Backlog) | 친구 궁합, 취향 변화 비교, 토스 로그인(사업자 등록 후), 관리자 페이지 |

> MVP에서는 후순위 기능의 진입 버튼(친구와 궁합 보기, 궁합 안내, 취향 변화 보기)을 숨긴다. 후순위 기능도 와이어프레임은 확정되어 있으므로 2장에 함께 명세하되, 화면 제목 옆에 **(후순위)** 로 표시한다.

### 1.6 공통 UI 컴포넌트

#### 1.6.1 상단 내비게이션 (토스 내비게이션 바)
- 모든 화면 상단은 토스 내비게이션 바(뒤로가기 ‹, 미니앱 로고·이름, ⋯, 닫기 ×)를 사용한다
- 앱 자체 헤더와 뒤로가기 버튼은 만들지 않는다(토스 뒤로가기와 중복 노출 금지)
- 홈 화면에는 뒤로가기가 없으며, 뒤로가기 시 미니앱이 종료된다
- 화면별 뒤로가기 목적지는 [3.7절](#37-뒤로가기-목적지) 참조

#### 1.6.2 화면 기본 구조
- 상단: 영문 대문자 라벨(eyebrow) + 굵은 한글 헤드라인 + 보조 문장
- 하단: 메인 버튼 1개(민트색 알약형, 오른쪽 화살표). 조건 미충족 시 비활성화
- 보조 버튼은 흰 배경 + 테두리의 알약형, 텍스트 링크는 "문구 →" 형태

#### 1.6.3 태그(Taste Tag)
- `#키워드` 형태의 작은 칩. 흰 배경 + 얇은 테두리
- 강조가 필요한 첫 번째 태그는 민트 배경으로 표시

#### 1.6.4 안내 박스(Notice)
- 점선 테두리 박스 + 아이콘 + 한 줄 문구. 힌트·주의·기기 저장 안내 등에 사용

#### 1.6.5 토스트
- 동작 결과를 화면 하단에 2~3초 노출한다. 문구는 [3.6절](#36-토스트-문구) 참조

#### 1.6.6 확인 팝업(Confirm Dialog)
- 되돌릴 수 없는 액션(기록 전체 삭제)은 화면 중앙 팝업으로 확인받는다
- 배경은 반투명 어두운 오버레이로 덮이고, 팝업에는 라벨·제목·설명·취소/실행 버튼 2개가 노출된다([2.14절](#214-기록-삭제-확인-scr-archive-delete) 참조)

#### 1.6.7 토스 공통 메뉴
- 문의, 신고, 일반 공유는 토스 ⋯ 메뉴의 공통 기능(고객센터)을 사용한다. 문의 답변은 앱인토스 콘솔에서 처리한다

## 2. 화면별 상세 기능 명세

### 2.1 첫 방문 홈 (SCR-HOME)

**화면 목적**: 지난 이슈가 없는 사용자에게 서비스를 소개하고 첫 번역을 시작하게 한다.

> 회원가입·로그인 단계 없이 바로 시작한다. 앱 실행 시 익명 기기 ID를 확인하고 없으면 생성한다(3.1절).

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `YOUR MUSIC, ANOTHER WORLD.` / "좋아하는 음악을 다른 취향의 언어로." / "플레이리스트에서 시작되는 나만의 작은 취향 잡지." |
| 콜라주 이미지 | 표시 | CD 플레이어·CD·사진·향수병 콜라주 + 말풍선 "음악 너머의 나를 만나봐!" + 손글씨 "a little more like you ↗" |
| 내 취향 번역하기 | 주요 CTA(민트) | 음악 입력(SCR-INPUT)으로 이동 |
| 흐름 표시 | 표시 | `MUSIC → TASTE → YOUR WORLD`, `MOVIE · BOOK · TRAVEL · PERFUME` |
| 안내 문구 | 표시 | "좋아하는 3곡이면 충분해요. 약 1분 정도 걸려요." |
| 하단 정보 링크 | 텍스트 링크 3종 | 서비스 소개(SCR-ABOUT) / 이용 약관(SCR-TERMS) / 개인정보 처리방침(SCR-PRIVACY) |

**예외 처리**
- 지난 이슈 확인에 실패하면 첫 방문 홈을 노출한다

---

### 2.2 재방문 홈 · 허브 (SCR-HOME-RETURN)

**화면 목적**: 지난 이슈가 있는 사용자의 메인 화면. 하단 탭 바를 대신해 새 번역, 지난 이슈, 궁합, 서비스 정보로 연결한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 데이터 소스 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `WELCOME BACK.` / "다시 펼친 당신의 취향 잡지." / "지난 이슈를 다시 읽거나, 새로운 음악으로 다음 호를 만들어요." |
| 지난 이슈 전체 보기 | 텍스트 링크 | `MY ISSUES` 라벨 우측. 아카이브(SCR-ARCHIVE)로 이동 |
| 최근 이슈 카드 | 카드 | 가장 최근 이슈 1건: {무드 이미지 커버}, {날짜 · 이슈 번호}, {취향 이름}, {대표 곡 외 n곡}, {태그}, `다시 펼쳐보기`. 클릭 시 해당 이슈의 취향 프로필(SCR-PROFILE) |
| 궁합 안내 (후순위) | 안내 박스(점선) | "친구와 취향 궁합을 볼까요? 링크 하나면 돼요." 클릭 시 최근 이슈 기준 궁합 초대 보내기(SCR-MATCH-SEND). 친구가 분석을 마친 궁합이 있으면 "궁합이 도착했어요"로 바뀌고, 클릭 시 궁합 결과(SCR-MATCH-RESULT)로 이동 |
| 새로운 취향 번역하기 | 주요 CTA(민트) | 음악 입력(SCR-INPUT)으로 이동 |
| 하단 정보 링크 | 텍스트 링크 3종 | 서비스 소개 / 이용 약관 / 개인정보 처리방침 |

> 화면 진입 및 포그라운드 복귀 시 데이터를 다시 조회한다.

---

### 2.3 음악 입력 (SCR-INPUT)

**화면 목적**: 취향 분석의 재료가 될 음악 3~5곡을 선택받는다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 유효성 규칙 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `TASTE SOURCE : MUSIC` / "당신의 취향을 들려주세요." / "요즘 가장 자주 듣는 음악 3–5곡. 유명한 곡보다, 당신다운 곡이면 좋아요." |
| 검색창 | 텍스트 입력 | 플레이스홀더 "곡 또는 아티스트를 검색하세요". 클릭 시 검색 상태(SCR-INPUT-SEARCH) |
| 선택 개수 | 표시 | `MY TRACKS {n} / 5` |
| 선택한 곡 카드 | 카드 리스트 | {앨범 아트}, {곡명}, {아티스트}, × 버튼. × 클릭 시 목록에서 제거하고 개수 갱신 |
| 힌트 | 안내 박스 | "반복해서 듣는 노래에 취향의 힌트가 있어요." |
| 이 음악들로 번역하기 | 주요 CTA(민트) | 3곡 이상일 때 활성화. 클릭 시 분석 요청 → 분석 중(SCR-ANALYSIS) 이동 |
| 선택 상태 안내 | 표시 | 3곡 이상: "{n}곡 선택 완료 · 조금 더 추가해도 좋아요" |

**입력 규칙**

| 규칙 | 내용 |
|---|---|
| 최소 곡 수 | 3곡. 미만이면 메인 버튼 비활성화 |
| 최대 곡 수 | 5곡. 초과 추가 불가 |
| 중복 | 같은 곡(곡 고유 ID 기준)은 한 번만 선택 가능 |
| 선택 유지 | 분석 화면에서 뒤로 오거나 재시도 상태에서 "음악 다시 고르기"로 돌아와도 선택이 유지된다 |

---

### 2.4 음악 검색 (SCR-INPUT-SEARCH)

**화면 목적**: 음악 입력 화면의 검색 상태. 검색 결과에서 곡을 담고 입력 검증 결과를 안내한다.

> 별도 화면이 아니라 음악 입력 화면의 상태이다. 뒤로가기 시 검색 상태만 해제된다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 검색창 | 텍스트 입력 | 입력이 멈춘 뒤 짧은 지연 후 iTunes Search API를 호출해 결과를 갱신(3.9절) |
| 검색 결과 | 리스트 | {썸네일}, {곡명}, {아티스트}, `+ 담기` 버튼 |
| + 담기 | 인라인 버튼 | 선택 목록에 추가하고 개수 갱신 |
| 담은 곡 | 표시(비활성) | 이미 선택한 곡은 `담은 곡`으로 표시하며 클릭할 수 없다 |
| 현재 선택 목록 | 카드 리스트 | 결과 아래에 `MY TRACKS {n} / 5`와 선택한 곡 카드 노출 |
| 경고 박스 | 안내 박스 | 3곡 미만일 때 "{n}곡만 더 고르면 번역할 수 있어요. (최소 3곡)" |
| 메인 버튼 | 주요 CTA(비활성) | 3곡 미만이면 흐리게 비활성화. 하단 문구 "{n}곡 선택 · 같은 곡은 한 번만 담을 수 있어요" |

**예외 처리**
- 검색 결과가 없으면 "찾는 곡이 없어요. 아티스트 이름으로도 검색해 보세요." 노출
- 5곡을 채운 상태에서 추가 시도 시 "최대 5곡까지 선택할 수 있어요." 토스트 노출
- 네트워크 오류 시 재시도 안내 토스트 노출

---

### 2.5 분석 중 (SCR-ANALYSIS)

**화면 목적**: 분석이 진행되는 동안 단계별 진행 상황을 보여주고, 완료되면 취향 프로필로 이동시킨다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `EDITING YOUR TASTE / 03` / "음악 사이에 숨은 당신을 읽는 중." / "멜로디에서 감각을 골라내고 있어요." |
| 분석 일러스트 | 표시 | `MUSIC ↓ MOOD ↓ TASTE` + 키워드 스티커(예: dreamy, nostalgic, warm & quiet) |
| 진행 바 | 표시 | `TRANSLATING YOUR WORLD {현재} / 04` + 민트색 진행 바 |
| 진행 단계 4종 | 리스트 | 01 음악의 분위기 듣기 / 02 감각 키워드 추출 / 03 나만의 취향 해석 / 04 다른 세계로 번역. 완료 ✓, 진행 중 ••• |
| 내 취향 프로필 보기 | 주요 CTA(다크) | 분석 중에는 비활성화, 완료되면 활성화. 클릭 시 취향 프로필(SCR-PROFILE) 이동 |
| 안내 문구 | 표시 | "거의 다 왔어요. 당신의 첫 번째 이슈를 만드는 중." |

**동작**
- 진행 단계는 연출로 표시한다. 01~03단계는 정해진 시간 간격으로 넘어가고, 04단계는 외부 API 조회가 시작될 때 표시하며, 모든 조회가 끝나면 완료로 바꾼다. 30초 안에 완료되지 않으면 재시도 상태(SCR-ANALYSIS-RETRY)로 전환한다
- 분석이 완료되면 새 이슈가 생성되고 메인 버튼이 활성화된다. 자동 이동은 하지 않는다. 프로필로 이동한 뒤에는 뒤로가기로 분석 화면에 돌아오지 않도록 처리한다
- 궁합 초대 흐름에서는 메인 버튼이 궁합 결과(SCR-MATCH-RESULT)로 이동한다
- 분석 중 뒤로가기 시 분석을 취소하고 음악 입력으로 돌아간다

---

### 2.6 분석 재시도 (SCR-ANALYSIS-RETRY)

**화면 목적**: 분석이 실패하거나 시간이 초과되었을 때 상황을 안내하고 다시 시도할 수 있게 한다.

> 별도 화면이 아니라 분석 중 화면의 오류 상태이다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `EDITING PAUSED / 03` / "잠시, 번역이 멈췄어요." / "음악을 읽는 데 평소보다 오래 걸리고 있어요." |
| 멈춘 일러스트·진행 바 | 표시 | 마지막 단어 자리에 `· · ·`, 진행 바는 회색 |
| 진행 단계 | 리스트 | 실패한 단계에 붉은 글씨 "다시 시도 필요" |
| 안내 | 안내 박스 | "고른 음악은 그대로 남아 있어요. 네트워크를 확인해 주세요." |
| 다시 번역하기 | 주요 CTA(민트) | 같은 곡으로 다시 분석 요청 → 분석 중 상태로 전환 |
| 음악 다시 고르기 | 텍스트 링크 | 음악 입력(SCR-INPUT) 이동(선택 유지) |

---

### 2.7 취향 프로필 (SCR-PROFILE)

**화면 목적**: 분석 결과인 취향 이름, 해설, 태그, 8개 감각 축을 보여주고 번역·공유·궁합으로 연결한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 데이터 소스 |
|---|---|---|
| 라벨 | 표시 | `YOUR TASTE PROFILE` + `VOL. {이슈 번호}` |
| 취향 이름 | 동적 텍스트 | {취향 이름} — AI 생성 (예: "비 오는 밤의 아날로그 로맨티스트") |
| 취향 해설 | 동적 텍스트 | {해설 두 줄} — AI 생성 |
| 무드 이미지 띠 | 표시 | {무드 이미지 — 자체 이미지 풀에서 고른 1장(3.10절)} + 고정 말풍선 `this is so you.` 이미지가 없으면 기본 이미지 |
| 태그 | 태그 4개 | {취향 키워드}. 첫 번째 태그 민트 강조 |
| 8개 감각 축 | 인포그래픽 | `THE SHAPE OF YOUR TASTE · 8 NOTES`. 축마다 좌·우 라벨과 점 위치({축 점수}). 축 정의는 3.4절 |
| 취향 카드 공유 | 보조 버튼 | 저장·공유(SCR-SHARE) 이동 |
| 친구와 궁합 보기 (후순위) | 보조 버튼 | 궁합 초대 보내기(SCR-MATCH-SEND) 이동 |
| 다른 세계로 번역하기 | 주요 CTA(민트) | 분야별 번역(SCR-TRANSLATE) 영화 탭으로 이동 |

**읽기 전용 모드**
- 취향 카드 공유 링크로 진입한 다른 사용자에게는 취향 프로필만 읽기 전용으로 보여주고(분야별 번역과 추천 상세는 볼 수 없다), 공유·궁합 버튼은 숨기며, 메인 버튼을 "나도 번역해보기"(음악 입력 이동)로 대체한다

**예외 처리**
- 공유 링크가 만료되었거나 잘못된 경우 홈으로 이동시키고 안내 토스트를 노출한다

---

### 2.8 분야별 번역 (SCR-TRANSLATE)

**화면 목적**: 취향 프로필을 영화·책·여행·향수 4개 분야의 추천으로 번역해 보여준다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 데이터 소스 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `YOUR TASTE, TRANSLATED.` / "이 취향을 다른 세계로 번역하면?" |
| 분야 탭 | 단일 선택 pill | `MOVIE` / `BOOK` / `TRAVEL` / `PERFUME`. 기본값 MOVIE. 선택된 탭은 검은 배경 |
| 추천 이미지 | 표시 | {추천 대상 이미지} — 영화: TMDB 포스터 / 책: 카카오 책 표지 / 여행지: 자체 이미지 풀 / 향수: 향수 DB 이미지. 없으면 분야별 기본 일러스트. 클릭 시 추천 상세 |
| 분야 표시 | 표시 | `TRANSLATED TO : {FILM / BOOK / TRAVEL / PERFUME}` |
| 취향 연결 배지 | 표시 | `취향 연결 {점수}%` (3.5절) |
| 추천 제목 | 동적 텍스트 | {추천 대상 이름}. 클릭 시 추천 상세(SCR-DETAIL) |
| 추천 이유 | 박스 | 라벨 `WHY IT FEELS LIKE YOU` + {추천 이유 1~2문장} — AI 생성 |
| 태그 | 태그 1~3개 | {추천 대상 키워드} |
| 다음 추천 | 리스트 아이템 | `ANOTHER PAGE FOR YOU` + {같은 분야의 다른 추천: 이미지, 이름, 한 줄 설명}. 클릭 시 해당 추천 상세 |

> 와이어프레임에는 "다음 추천"과 "취향 연결 배지"가 영화 탭에만 그려져 있으나, 모든 분야에 같은 구조로 적용한다. 분야당 추천은 3건이며, 대표 1건은 큰 카드로, 나머지 2건은 "다음 추천" 목록으로 보여준다.
> 탭 전환은 뒤로가기 단계에 쌓이지 않는다.

---

### 2.9 추천 상세 (SCR-DETAIL)

**화면 목적**: 개별 추천의 정보와, 사용자의 음악과 어떻게 연결되는지에 대한 근거를 보여준다.

> 분야(영화·책·여행·향수)와 상관없이 같은 구조를 사용하며, 표시 내용만 달라진다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 데이터 소스 |
|---|---|---|
| 대표 이미지 | 표시 | {추천 대상 이미지} (2.8절과 같은 규칙) |
| 라벨 | 표시 | `{분야} / TASTE NOTE {순번}` |
| 제목 | 동적 텍스트 | {추천 대상 이름} |
| 메타 정보 | 동적 텍스트 | 분야별 한 줄 정보(아래 표) |
| 소개 | 동적 텍스트 | {추천 대상 소개 1~2문장} |
| 연결 근거 | 매핑 리스트(3줄) | 라벨 `WHY IT MATCHES YOUR TASTE`. 좌측 `YOUR MUSIC`, 우측 `THIS FILM / BOOK / PLACE / SCENT`. {내 음악의 특징} → {추천 대상의 특징} |
| 근거 문장 | 동적 텍스트 | {사용자가 고른 곡 이름이 포함된 연결 설명 1~2문장} — AI 생성 |
| 이 번역에 답해주기 | 주요 CTA(민트) | 반응(SCR-FEEDBACK) 이동 |

> 와이어프레임 초안에 있던 저장(북마크) 아이콘은 제거되었다. 추천 저장 기능은 제공하지 않는다(4.1절).

**분야별 메타 정보**

| 분야 | 메타 정보 구성 | 우측 라벨 |
|---|---|---|
| 영화 | 원제 · 개봉 연도 | THIS FILM |
| 책 | 원제 · 출간 연도 · 저자 | THIS BOOK |
| 여행지 | 지역 · 추천 계절 · 여행 성격 | THIS PLACE |
| 향수 | 이름 · 계열 · 주요 노트 | THIS SCENT |

**항목별 출처**

| 분야 | 외부 API · DB에서 가져오는 항목 | OpenAI가 작성하는 항목 |
|---|---|---|
| 영화 | 포스터, 원제, 개봉 연도 (TMDB) | 소개 1~2문장, 추천 이유, 연결 근거, 근거 문장, 태그 |
| 책 | 표지, 저자, 출간 연도 (카카오 책 검색) | 소개 1~2문장, 추천 이유, 연결 근거, 근거 문장, 태그 |
| 여행지 | 지역 (OpenTripMap), 이미지 (자체 이미지 풀) | 추천 계절, 여행 성격, 소개 1~2문장, 추천 이유, 연결 근거, 근거 문장, 태그 |
| 향수 | 이름, 브랜드, 계열, 주요 노트, 이미지 (향수 DB) | 소개 1~2문장, 추천 이유, 연결 근거, 근거 문장, 태그 |

---

### 2.10 반응 (SCR-FEEDBACK)

**화면 목적**: 추천이 사용자의 취향과 맞았는지 스탬프로 반응을 받아 기록한다. 이후 추천에는 반영하지 않는다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `A NOTE FROM YOU` / "이 번역, 나랑 닮았나요?" / "맞고 틀린 답은 없어요. 당신의 감각을 스탬프로 남겨주세요." |
| 말풍선 | 표시 | "음악만큼, 이것도 좋아요?" |
| 스탬프 4종 | 단일 선택(2×2) | 완전 내 취향(THAT'S ME) / 조금 비슷해(CLOSE ENOUGH) / 잘 모르겠어(MAYBE LATER) / 내 취향 아니야(NOT MY MOOD). 선택 시 민트 배경 |
| 안내 문구 | 표시 | "이 감각을 기억해서, 다음 번역을 더 당신답게." |
| 스탬프 남기고 취향 카드 보기 | 주요 CTA(민트) | 스탬프를 고르면 활성화. 저장·공유(SCR-SHARE) 이동 |

**동작**
- 스탬프 선택은 필수이며, 고르기 전에는 메인 버튼이 비활성화된다. 스탬프는 하나만 선택할 수 있으며, 다른 스탬프를 누르면 선택이 바뀐다. 이미 스탬프를 남긴 추천에 다시 들어오면 이전 선택이 표시된 상태로 시작한다
- 선택 즉시 해당 추천에 스탬프를 저장하고 "당신의 감각을 기억할게요." 토스트를 노출한다

**예외 처리**
- 저장에 실패하면 선택을 되돌리고 재시도 안내 토스트를 노출한다

---

### 2.11 저장 · 공유 (SCR-SHARE)

**화면 목적**: 이슈를 한 장의 취향 카드로 만들어 이미지로 저장하거나 토스로 공유한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `KEEP YOUR TASTE.` / "한 장으로 남기는 나의 취향." |
| 취향 카드 | 표시 | `MY TASTE` + `ISSUE {번호}`, {취향 이름}, 콜라주 이미지, 스티커 "translated from music ♡", {태그}, `MUSIC → MOVIE · BOOK · TRAVEL · PERFUME`, "취향 번역기 · PERSONAL TASTE MAGAZINE" |
| 이미지 저장 | 보조 버튼 | 카드를 이미지 파일로 저장. "취향 카드를 저장했어요." 토스트 |
| 카드 공유 | 주요 CTA(민트) | 토스 공유 링크 생성 후 공유 창 호출. 링크 미리보기 이미지는 취향 카드 |
| 내 취향 아카이브에서 다시 보기 | 텍스트 링크 | 아카이브(SCR-ARCHIVE) 이동 |
| 처음 화면으로 | 텍스트 링크 | 재방문 홈(SCR-HOME-RETURN) 이동. 이전 단계를 모두 비운다 |

**예외 처리**
- 이미지 저장 또는 공유 링크 생성에 실패하면 안내 토스트를 노출한다

---

### 2.12 아카이브 (SCR-ARCHIVE)

**화면 목적**: 지난 이슈를 모아 보여주고, 취향 변화 확인과 기록 관리로 연결한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 데이터 소스 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `MY TASTE ARCHIVE` / "차곡차곡, 나를 닮은 이슈들." / "취향은 변해도, 기록은 남으니까." + `{이슈 개수} ISSUES` |
| 최신 이슈 | 카드(큰 커버) | 커버({무드 이미지}, `MY TASTE / ISSUE {번호}`, {취향 이름}) + {날짜}, {취향 이름}, {대표 곡 외 n곡}, {태그}, `이슈 펼쳐보기 →` |
| 이전 이슈 | 카드 리스트(작은 커버) | 같은 정보를 최신순으로 이슈 수만큼 노출 |
| 안내 | 안내 박스 | "나의 취향 잡지에, 다음 이야기를 더해볼까요?" |
| 취향 변화 보기 (후순위) | 텍스트 링크 | 취향 변화(SCR-ARCHIVE-CHANGE) 이동. 이슈가 2개 이상일 때만 노출 |
| 기록 관리 · 전체 삭제 | 텍스트 링크(경고색) | 기록 삭제 확인(SCR-ARCHIVE-DELETE) 팝업 노출 |
| 새로운 취향 번역하기 | 주요 CTA(민트) | 음악 입력(SCR-INPUT) 이동 |

> 이슈 카드 클릭 시 해당 이슈의 취향 프로필(SCR-PROFILE)로 이동한다.
> 이슈가 없을 경우 빈 상태(empty state) 문구와 "첫 번째 취향 번역하기" 버튼을 노출한다.

### 2.13 취향 변화 (SCR-ARCHIVE-CHANGE) (후순위)

**화면 목적**: 두 이슈의 감각 축을 비교해 취향이 어떻게 달라졌는지 보여준다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `HOW YOUR TASTE MOVED` / "지난 이슈로 본 취향의 변화." / {변화 요약 한 줄} |
| 비교 대상 | 태그 2개 | `ISSUE {번호} · {월}` → `ISSUE {번호} · {월}`. 기본값은 직전 이슈 → 최신 이슈. 태그 클릭 시 비교 대상 변경 |
| 축 변화 | 인포그래픽 | `THE SHIFT`. 축마다 이전 값(회색 점)과 현재 값(민트 점) |
| 안내 문구 | 표시 | "이슈가 쌓일수록 변화가 더 선명해져요." |
| 기기 저장 안내 | 안내 박스 | "기록은 이 기기에만 저장돼요. 기기를 바꾸거나 앱을 지우면 사라질 수 있어요." |
| 새로운 취향 번역하기 | 주요 CTA(민트) | 음악 입력 이동 |

### 2.14 기록 삭제 확인 (SCR-ARCHIVE-DELETE)

**화면 목적**: 모든 기록을 삭제하기 전, 삭제 범위와 되돌릴 수 없음을 안내하고 최종 확인을 받는다. (팝업)

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 배경 | 오버레이 | 아카이브 화면 위에 반투명 어두운 오버레이 |
| 라벨·타이틀 | 표시 | `CLEAR ARCHIVE` / "모든 이슈를 지울까요?" |
| 설명 문구 | 표시 | "이 기기에 저장된 이슈와 스탬프가 모두 지워지고, 되돌릴 수 없어요." |
| 취소 | 보조 버튼 | 팝업 닫기(데이터 변화 없음) |
| 삭제하기 | 경고 CTA(다크) | 서버와 기기의 모든 기록을 삭제하고 첫 방문 홈(SCR-HOME)으로 이동 |

> 삭제 범위: 이슈, 추천, 스탬프, 궁합 초대·결과. 삭제 후 익명 기기 ID를 새로 발급한다(4.4절).

### 2.15 궁합 초대 보내기 (SCR-MATCH-SEND) (후순위)

**화면 목적**: 내 취향 카드를 친구에게 보내 궁합을 요청한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `INVITE A FRIEND` / "친구의 음악과 겹쳐볼까요?" / "내 취향 카드를 보내면, 친구가 음악을 고르는 순간 둘의 궁합이 도착해요." |
| 초대 카드 미리보기 | 표시 | `MY TASTE` + `INVITATION`, {내 취향 이름}, 말풍선 "너는 어떤 음악 들어?", {태그} |
| 별명 입력 | 텍스트 입력 | 친구에게 보일 이름. 최대 8자, 비우면 "친구"로 표시 |
| 진행 안내 | 리스트 | `HOW IT WORKS` 01 초대 링크 보내기 / 02 친구가 음악 3곡 고르기 / 03 둘의 궁합 도착 |
| 안내 | 안내 박스 | "친구는 가입 없이 토스에서 링크를 바로 열 수 있어요." |
| 링크 복사 | 보조 버튼 | 초대 링크를 클립보드에 복사 + 안내 토스트 |
| 토스로 초대 | 주요 CTA(민트) | 토스 공유 창 호출 |
| 궁합이 도착하면 이렇게 보여요 | 텍스트 링크 | 궁합 결과(SCR-MATCH-RESULT) 예시 |

> 기준 이슈는 진입한 화면의 이슈(취향 프로필) 또는 최근 이슈(재방문 홈)이다.
> 초대 링크는 생성 후 7일간 유효하다. 보낸 사람 본인이 링크를 열면 이 화면으로 이동한다. 궁합 결과가 도착하면 푸시 알림 없이 재방문 홈의 궁합 안내에 표시한다(2.2절).

### 2.16 궁합 초대 받기 (SCR-MATCH-INVITE) (후순위)

**화면 목적**: 초대 링크를 연 친구에게 보낸 사람의 취향을 보여주고, 본인의 음악을 고르게 한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `A LETTER FROM A FRIEND` / "{보낸 사람 이름} 님이 취향 궁합을 보냈어요." / "서로의 음악으로, 둘이 닮은 세계를 찾아봐요." |
| 친구 취향 카드 | 표시 | `FRIEND'S TASTE` + `ISSUE {번호}`, {보낸 사람의 취향 이름}, 말풍선, {태그} |
| 진행 안내 | 리스트 | 01 내 음악 3곡 고르기 / 02 둘의 감각 겹쳐보기 / 03 함께 볼 영화 받기 |
| 내 음악으로 궁합 보기 | 주요 CTA(민트) | 음악 입력(SCR-INPUT) 이동. 이후 분석 완료 시 궁합 결과로 이동 |
| 안내 문구 | 표시 | "가입 없이 바로 시작해요." |

**예외 처리**
- 초대 링크가 만료되었거나 잘못된 경우 홈으로 이동시키고 안내 토스트를 노출한다

> 이 흐름에서는 음악 입력과 분석 화면을 거치는 동안 초대 정보를 유지한다. 친구에게도 이슈가 1건 생성된다.

### 2.17 궁합 결과 (SCR-MATCH-RESULT) (후순위)

**화면 목적**: 두 사람의 취향이 얼마나 닮았는지와 함께 즐길 추천을 보여준다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 데이터 소스 |
|---|---|---|
| 라벨 | 표시 | `TASTE MATCH` + `YOU × {친구 별명}` |
| 일치율 | 동적 텍스트 | "우리는 {일치율}% 닮은 취향." |
| 요약 | 동적 텍스트 | {두 사람 취향 비교 한 줄} — AI 생성 |
| 두 사람 축 비교 | 인포그래픽 | `TWO SHAPES OF TASTE`. 축마다 점 2개(민트 = 나, 검정 = 친구) |
| 키워드 | 태그 | `SAME MOOD` {겹치는 키워드} / `DIFFERENT TEMPO` {다른 키워드} |
| 함께 볼 추천 | 리스트 아이템 | `TOGETHER, WATCH THIS` + {두 사람 모두에게 맞는 추천 1건: 이미지, 이름, 한 줄 이유}. 클릭 시 추천 상세 |
| 결과 저장 / 궁합 공유 | 보조 버튼 / 주요 CTA | 저장·공유(SCR-SHARE) 이동 |
| 내 취향 프로필 보기 | 텍스트 링크 | 본인 이슈의 취향 프로필(SCR-PROFILE) 이동 |
| 처음 화면으로 | 텍스트 링크 | 재방문 홈 이동 |

**지표 산정 로직**: 3.5절 참조. 결과 저장·궁합 공유로 이동한 저장·공유 화면은 취향 카드 대신 궁합 카드(두 사람 별명, 일치율, 겹치는 키워드)를 보여준다

### 2.20 개인정보 처리방침 (SCR-PRIVACY)

**화면 목적**: 수집하는 정보와 처리 방식을 안내한다.

| 요소 | 타입 | 설명 |
|---|---|---|
| 라벨·헤드라인 | 표시 | `PRIVACY POLICY` / "개인정보 처리방침." / 시행일 |
| 요약 박스 | 박스 | `IN SHORT` "이름 · 연락처 · 토스 계정 정보는 받지 않아요. 기기마다 만들어지는 익명 번호로만 기록을 구분해요." |
| 조항 | 리스트 | 아래 표 |

| 조항 | 내용 |
|---|---|
| 수집하는 정보 | 익명 기기 번호, 고른 음악 목록, 추천에 남긴 스탬프 |

### 3.5 추천 엔진 및 지표 산정 로직

추천 대상을 미리 DB로 구축하거나 임베딩하지 않는다. 분석과 추천 선정은 AI 모델(기본 OpenAI gpt-5.4-mini, 상황에 따라 Anthropic claude-sonnet-4-6)이 담당하고, 외부 API는 선정된 대상의 실제 정보를 가져오는 데 쓴다. 향수만 자체 DB(약 150건)를 쓴다.

| 단계 | 내용 |
|---|---|
| 1. 음악 검색 | 사용자가 입력한 곡명·가수명으로 iTunes Search API를 호출해 곡 정보(곡 ID, 곡명, 아티스트, 앨범 아트, 장르)를 가져와 화면에 보여준다 |
| 2. 취향 분석·추천 선정 | 선택한 3~5곡의 정보를 OpenAI API에 보내 한 번에 받는다: 8개 축 점수, 취향 이름·해설·태그, 분야별 추천 후보(제목과 조회용 정보, 추천 이유, 연결 근거 3줄, 근거 문장, 태그, 대상의 8개 축 점수) |
| 3. 향수 선정 | 향수는 자체 DB 목록을 프롬프트에 함께 보내, 그 안에서만 고르게 한다 |
| 4. 실제 정보 조회 | 분석 결과로 나온 제목으로 분야별 API를 호출한다. 영화: TMDB / 책: 카카오 책 검색 / 여행지: OpenTripMap / 향수: 자체 DB (3.9절) |
| 5. 검증 | 조회 결과가 없는 후보는 버린다. 이를 대비해 분야당 후보를 5건 받고, 조회에 성공한 순서대로 3건을 채택한다. 3건을 채우지 못하면 찾은 만큼만 보여준다 |
| 6. 결과 저장·재사용 | 분석 결과와 조회한 정보를 이슈에 저장한다. 같은 기기에서 같은 곡 조합으로 다시 분석하면 저장된 결과를 다시 사용한다 |

| 지표 | 산정 기준 |
|---|---|
| 취향 연결(%) | 사용자의 8개 축 점수와 OpenAI가 매긴 추천 대상의 8개 축 점수 차이를 서버에서 계산해 60~99%로 환산한 값. 임베딩은 쓰지 않는다 |
| 궁합 일치율(%) | 두 이슈의 8개 축 점수 차이를 평균해 0~100으로 환산한 값(차이가 작을수록 높음) |
| 겹치는 / 다른 키워드 | 두 사람의 점수가 가까운 축 / 먼 축에서 추출 |
| 함께 볼 추천 | 두 사람의 축 점수를 OpenAI에 보내 두 사람 모두에게 맞는 영화 1건을 받고 TMDB로 조회한다 |
| 스탬프 반영 | 스탬프는 저장하고 화면에 표시만 한다. 다음 분석과 추천에는 반영하지 않는다 |

> 표시 범위는 출발값이며, 구현 단계에서 테스트로 조정한다(4.2절).

### 3.9 외부 API 연동

| 용도 | API | 호출 시점 | 가져오는 정보 |
|---|---|---|---|
| 음악 검색 | [iTunes Search API](https://performance-partners.apple.com/search-api) | 음악 검색(SCR-INPUT-SEARCH)에서 입력할 때 | 곡 ID, 곡명, 아티스트, 앨범 아트, 장르 |
| 취향 분석·추천 선정 | OpenAI API | 분석 요청 시 1회 | 8개 축 점수, 취향 이름·해설·태그, 분야별 추천 후보와 설명 문장 |
| 영화 정보 | [TMDB API](https://developer.themoviedb.org/reference/getting-started) | 분석 직후, 영화 제목으로 검색 | 포스터, 원제, 개봉 연도, 줄거리 |
| 책 정보 | [카카오 책 검색 API](https://developers.kakao.com/docs/ko/daum-search/dev-guide#search-book) | 분석 직후, 책 제목으로 검색 | 표지, 저자, 출간일, 소개 |
| 여행지 정보 | [OpenTripMap API](https://dev.opentripmap.org/docs) | 분석 직후, 여행지 영문 이름으로 검색 | 지역, 좌표, 설명(영문). 이미지는 자체 이미지 풀 사용 |
| 향수 정보 | 자체 DB(약 150건) | 분석 직후, 향수 이름으로 조회 | 이름, 브랜드, 계열, 주요 노트, 이미지 |

**연동 규칙**

- OpenAI, TMDB, 카카오, OpenTripMap의 API 키는 서버에만 두고, 클라이언트는 우리 서버를 통해서만 호출한다. iTunes Search API는 키가 필요 없으므로 클라이언트에서 직접 호출한다(호출 한도가 사용자별로 적용되게 하기 위함)
- iTunes 검색은 `country=KR`, `media=music`, `entity=song`으로 호출한다. 분당 약 20회 제한이 있어, 입력이 멈춘 뒤에만 호출하고 같은 검색어는 다시 호출하지 않는다(4.2절)
- OpenAI 응답은 정해진 JSON 형식으로 받는다. 조회 정확도를 위해 영화는 원제와 개봉 연도, 책은 저자, 여행지는 영문 이름과 국가를 함께 받는다. 책은 국내 출간 제목으로 받고, 카카오 검색 결과 중 저자가 일치하는 것만 채택한다
- 외부 API 조회는 분야별로 동시에 진행한다. 한 분야의 조회가 실패해도 나머지 분야는 정상적으로 보여주고, 실패한 분야 탭에는 "이 분야의 번역을 불러오지 못했어요" 안내를 노출한다
- TMDB 정보를 쓰는 화면이 있으므로, 서비스 소개(SCR-ABOUT)에 TMDB 로고와 "This product uses the TMDB API but is not endorsed or certified by TMDB." 문구를 표기한다

> 본 문서에서 "OpenAI"라고 적은 부분은 분석에 쓰는 AI 모델을 뜻한다. 기본 모델은 OpenAI `gpt-5.4-mini`이고, 상황에 따라 Anthropic `claude-sonnet-4-6`으로 바꿀 수 있다. 모델을 바꿔도 요청·응답 형식과 검증 규칙은 같다. 전환 방법은 API 명세서 5.2절 참조.

**여행지 처리 규칙**

- OpenTripMap이 한국어를 제공하지 않는 경우, 여행지만 OpenAI가 영문 이름으로 결과를 내게 하고 그 영문 이름으로 OpenTripMap을 조회한다
- 조회 결과(이름, 지역, 설명)는 화면에 보여주기 전에 한국어로 번역한다. 번역된 내용을 이슈에 저장해 다시 번역하지 않는다
- 여행지 이미지는 OpenTripMap에서 가져오지 않는다. 팀이 저장해 둔 여행지 이미지 약 150장 중 해당 여행지와 일치하거나 분위기가 비슷한 이미지를 골라 보여준다
- 이미지는 DB 또는 별도 저장소에 두고 이미지 주소로 불러온다. 파일 이름에 장소와 분위기를 담아(예: `kyoto_alley_night`, `beach_sunset_calm`) 이름만으로 어울리는 이미지를 찾을 수 있게 한다. 파일 이름 목록을 OpenAI에 함께 보내 여행지마다 가장 어울리는 파일을 고르게 한다

### 3.10 자체 데이터 (향수 DB · 이미지 풀)

**향수(Perfume)** — 약 150건

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| perfume_id | string | Y | 향수 고유 식별자 |
| name | string | Y | 향수 이름 |
| brand | string | Y | 브랜드 |
| family | string | Y | 계열(예: 우디, 플로럴, 시트러스) |
| notes | array | Y | 주요 노트 |
| image_url | string | N | 제품 이미지 주소 |

**이미지 풀(Image)** — 약 150장. 여행지 이미지와 취향 프로필·이슈 커버의 무드 이미지에 함께 쓴다.

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| image_id | string | Y | 이미지 고유 식별자 |
| file_name | string | Y | 장소_특징_분위기 순서의 파일 이름(예: kyoto_alley_night) |
| image_url | string | Y | 이미지 주소 |
| kind | enum | Y | place(특정 장소) / mood(분위기 일반) |

- 무드 이미지는 분석 때 OpenAI가 파일 이름 목록에서 취향에 가장 어울리는 1장을 골라 이슈에 저장한다
- 고른 파일 이름이 목록에 없으면 기본 이미지를 쓴다

### 3.11 OpenAI 요청 · 응답 형식

| 구분 | 내용 |
|---|---|
| 보내는 값 | 선택한 곡 3~5건(곡명, 아티스트, 장르), 향수 목록(ID · 이름 · 계열 · 노트), 이미지 파일 이름 목록 |
| 받는 값 — 취향 | 8개 축 점수, 취향 이름, 해설 두 줄, 태그 4개, 무드 이미지 파일 이름 |
| 받는 값 — 추천 | 분야별 후보 5건. 후보마다 조회용 정보(영화: 제목 · 원제 · 개봉 연도 / 책: 국내 출간 제목 · 저자 / 여행지: 한글 이름 · 영문 이름 · 국가 · 추천 계절 · 여행 성격 · 이미지 파일 이름 / 향수: 향수 ID), 소개, 추천 이유, 연결 근거 3줄, 근거 문장, 태그, 8개 축 점수 |

- 응답은 정해진 JSON 형식으로만 받는다
- 응답이 형식에 맞지 않으면 1회 다시 요청하고, 그래도 실패하면 분석 재시도 상태(SCR-ANALYSIS-RETRY)로 전환한다

## 4. 주요 정책 및 설계 결정 사항

### 4.1 확정된 정책

| 영역 | 확정된 내용 |
|---|---|
| 인증 | 회원가입·로그인을 제공하지 않는다. 익명 기기 ID로 기록을 구분한다. |
| 내비게이션 | 하단 탭 바를 두지 않는다. 재방문 홈이 허브 역할을 하며, 흐름의 끝에는 "처음 화면으로" 링크를 둔다. |
| 상단 영역 | 토스 내비게이션 바를 사용하고, 앱 자체 헤더·뒤로가기 버튼은 만들지 않는다. |
| 설정 · 문의 | 설정 화면과 문의 화면을 두지 않는다. 문의·신고는 토스 ⋯ 메뉴의 고객센터로 대체한다. |
| 서비스 정보 | 서비스 소개·이용 약관·개인정보 처리방침은 홈 하단 링크로 제공한다. |
| 음악 입력 | 최소 3곡, 최대 5곡이며 같은 곡은 한 번만 선택할 수 있다. |
| 분석 완료 처리 | 자동 이동하지 않는다. 완료되면 "내 취향 프로필 보기" 버튼이 활성화된다. |
| 분석 시간 초과 | 30초 안에 완료되지 않으면 재시도 상태로 전환한다. |
| 분야당 추천 | 분야당 3건. 대표 1건은 큰 카드, 나머지 2건은 "다음 추천" 목록으로 보여준다. |
| 추천 대상 | 추천 대상은 OpenAI가 선정하고, 외부 API에서 실제로 조회된 대상만 보여준다. 향수는 자체 DB(약 150건) 안에서만 고른다. 추천 대상 DB 구축과 임베딩은 하지 않는다(3.5절). |
| 스탬프 | 선택은 필수이다. 스탬프를 고르기 전에는 저장·공유로 넘어갈 수 없다. 스탬프는 기록·표시용이며 추천에 반영하지 않는다. |
| 추천 저장 | 추천 저장(북마크) 기능은 제공하지 않는다. 저장은 저장·공유 화면의 취향 카드 이미지 저장만 남긴다. |
| 오늘의 번역 | 제공하지 않는다. 재방문 홈에서 해당 카드를 제거한다. |
| 지표 환산 | 취향 연결(%)은 축 점수 차이로 계산하고, 표시 범위는 60~99%로 한다(3.5절). |
| 글자 크기 | 보조 글자 최소 11px, 본문 14px 이상으로 한다. 영문 라벨만 10px까지 허용한다. |
| AI 생성 문장 고지 | 취향 이름, 해설, 추천 이유, 근거 문장은 AI가 생성하며, 서비스 소개와 이용 약관에 이를 고지한다. |
| 약관 · 처리방침 | 표준 예시를 바탕으로 초안을 작성하고, 출시 전 앱인토스 심사 기준과 대조한다. 처리방침에 AI 모델 제공사(OpenAI, Anthropic) 전송 사실을 명시한다. |
| 기록 삭제 | 아카이브의 "기록 관리"에서 전체 삭제하며, 삭제 전 확인 팝업을 반드시 거친다(4.4절). |
| 공유 | 공유 링크는 토스 공유 링크를 사용하며, 받은 사람은 가입 없이 토스에서 바로 연다. |
| 궁합 표시 이름 (후순위) | 초대를 보낼 때 별명을 입력받는다(최대 8자, 비우면 "친구"). 토스 로그인은 닉네임을 제공하지 않는다. |
| 초대 링크 (후순위) | 유효 기간은 7일이다. 본인이 자기 링크를 열면 초대 보내기 화면으로 이동한다. |
| 친구 흐름 (후순위) | 친구는 분석 후 바로 궁합 결과로 이동한다. 결과 화면에 "내 취향 프로필 보기" 링크를 둔다. |
| 궁합 결과 알림 (후순위) | 푸시 알림은 보내지 않는다. 재방문 홈의 궁합 안내에 "궁합이 도착했어요"를 표시한다. |
| 통신 | API 통신은 HTTPS만 사용한다. OpenAI·Anthropic·TMDB·카카오·OpenTripMap API 키는 서버에만 두고 클라이언트에서 직접 호출하지 않는다. |

### 4.2 열린 이슈 (Open Issues)

기존 열린 이슈 13건은 2026-10-02에 모두 결정되어 4.1절로 옮겼다. 아래는 구현하면서 확인이 필요한 항목이다.

| 영역 | 확인 필요 사항 |
|---|---|
| iTunes 호출 한도 | iTunes Search API는 분당 약 20회로 제한된다. 클라이언트에서 직접 호출하는 것으로 확정했다(3.9절). 토스 미니앱 환경에서 직접 호출이 막히지 않는지(교차 출처 제한) 실제 호출로 확인한다 |
| iTunes 이용 조건 | 앨범 아트 사용 시 스토어 링크 배지를 함께 두라는 조건이 있다. 적용 범위를 확인한다 |
| 여행지 조회 품질 | OpenTripMap의 한국어 제공 여부를 실제 호출로 확인한다. 제공하지 않으면 3.9절의 영문 조회 · 한국어 번역 방식을 적용한다. 여행지 이미지 약 150장의 수집과 사용 권한 확인이 필요하다 |
| 추천 후보 검증률 | OpenAI가 낸 제목이 각 API에서 실제로 찾아지는 비율을 측정하고, 후보 개수(5건)를 조정한다 |
| 수치 조정 | 분석 시간 초과 30초와 취향 연결 표시 범위 60~99%는 출발값이다. OpenAI 호출 1회에 외부 API 조회가 더해지므로 실제 응답 시간을 재서 조정한다 |
| 분석 횟수 제한 | 개발 단계에서는 제한을 두지 않는다. 출시 전에 OpenAI 비용을 보고 기기당 하루 상한을 정한다 |
| 약관 · 처리방침 본문 | 초안 작성과 시행일 확정, 앱인토스 심사 기준 대조 |
| 익명 키 도입 | 앱인토스 `getAnonymousKey`로 익명 기기 ID를 대체할 수 있는지, 사업자 등록 없이 쓸 수 있는지 확인 |
| 토스 닉네임 | 게임 프로필 API(`Game.getUserProfile`)를 비게임 미니앱에서 쓸 수 있는지 확인. 가능하면 별명 입력을 대체할지 검토 |

> 반응 화면의 안내 문구 "이 감각을 기억해서, 다음 번역을 더 당신답게."는 스탬프를 추천에 반영하지 않더라도 기존 그대로 유지한다(2026-10-02 결정).

### 4.3 앱인토스 대응 방식

- 토스 내비게이션 바를 사용하며, 모든 화면에서 뒤로가기가 3.7절대로 동작해야 한다
- 미니앱 이름과 로고는 콘솔에 등록한 브랜드와 일치시킨다
- ⋯ 메뉴의 공통 기능(고객센터·신고·공유)이 정상 노출되어야 한다
- 와이어프레임 상단의 시계 줄(상태 바)과 로고 헤더는 목업 표현이며, 실제 구현에서는 토스 내비게이션 바로 대체한다
- 토스 로그인은 사업자 등록이 필요하므로 본 범위에서 제외한다(5장)

### 4.4 기록 삭제 정책 상세

- 삭제 대상: 해당 기기 ID에 연결된 이슈, 추천, 스탬프, 궁합 초대·결과 전체
- 삭제 후 처리: 익명 기기 ID를 새로 발급하고 첫 방문 홈으로 이동한다
- 삭제 확인: 팝업에서 "취소/삭제하기" 확인 절차를 거친다(2.14절)
- 삭제 후 복구는 불가하다. 이미 공유된 링크는 더 이상 열리지 않는다(가정)

### 4.5 예시 데이터 취급

- 와이어프레임의 곡명, 취향 이름, 추천 작품, 사진, 점수는 예시이다. 구현 시 고정 값으로 넣지 않고 분석·추천 결과로 채운다
- 추천 이미지가 없을 때 쓰는 분야별 기본 일러스트(책 표지·풍경·향수병 등)는 와이어프레임의 일러스트를 기준으로 한다

## 6. 화면 흐름 (User Flow)

- 앱 실행 → (지난 이슈 없음) → 첫 방문 홈
- 앱 실행 → (지난 이슈 있음) → 재방문 홈
- 첫 방문 홈 / 재방문 홈 → (메인 버튼) → 음악 입력
- 음악 입력 → (검색창) → 음악 검색 → (+ 담기) → 음악 입력
- 음악 입력 → (이 음악들로 번역하기) → 분석 중 → (완료 후 내 취향 프로필 보기) → 취향 프로필
- 분석 중 → (실패·시간 초과) → 분석 재시도 → (다시 번역하기) → 분석 중
- 분석 재시도 → (음악 다시 고르기) → 음악 입력
- 취향 프로필 → (다른 세계로 번역하기) → 분야별 번역 → (이미지·제목) → 추천 상세
- 추천 상세 → (이 번역에 답해주기) → 반응 → (스탬프 남기고 취향 카드 보기) → 저장·공유
- 저장·공유 → (처음 화면으로) → 재방문 홈
- 저장·공유 → (내 취향 아카이브에서 다시 보기) → 아카이브
- 취향 프로필 → (취향 카드 공유) → 저장·공유
- 재방문 홈 → (지난 이슈 전체 보기) → 아카이브 → (이슈 카드) → 취향 프로필
- 재방문 홈 → (최근 이슈 카드) → 취향 프로필
- 재방문 홈 → (궁합이 도착했어요) → 궁합 결과
- 아카이브 → (취향 변화 보기) → 취향 변화
- 아카이브 → (기록 관리 · 전체 삭제) → 삭제 확인 팝업 → (삭제하기) → 첫 방문 홈
- 취향 프로필 / 재방문 홈 → (친구와 궁합) → 궁합 초대 보내기 → (토스로 초대) → 친구에게 링크 전송
- 궁합 초대 링크 → 궁합 초대 받기 → (내 음악으로 궁합 보기) → 음악 입력 → 분석 중 → 궁합 결과
- 궁합 결과 → (함께 볼 추천) → 추천 상세
- 궁합 결과 → (처음 화면으로) → 재방문 홈
- 취향 카드 공유 링크 → 취향 프로필(읽기 전용) → (나도 번역해보기) → 음악 입력
- 홈 → (하단 정보 링크) → 서비스 소개 / 이용 약관 / 개인정보 처리방침
